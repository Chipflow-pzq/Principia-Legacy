# Personal research exploration

**Reader 1.5.0rc1 · local review candidate.** The public site remains on accepted 1.4.1 until owner acceptance. Generated maps never enlarge or modify the canonical corpus.

## Try it

1. Open **Explore**. The same input card offers **Browse the atlas** and **Trace a discovery**. The second action reveals a specific research input for a paper, technique or scientific advance. Switching from a public search can prefill it.
2. Enter your own SiliconFlow API key in the top-right global **Settings**. The default is `deepseek-ai/DeepSeek-V4.1-Flash`; an existing saved selection is preserved. **Load my available models** discovers exact IDs from your account without changing your selection. Model availability and pricing are determined by SiliconFlow.
3. Select **Build research map**. The agent retrieves passages, plans bounded follow-up searches, streams the insights, connects the complete set and challenges its claims and connections. The progress panel shows stages, source counts, recent activity, arriving insights, elapsed time and an approximate remaining-time range. The final evidence review shows counts of completed verdicts and a firm 60-second limit. **Inspect draft now** opens the map while the check continues.
4. Click an insight or arrow, or use **List** and the accessible connection list. Inspect the quotation, attribution, assumptions and limits. Use connection filters to distinguish history, reasoning, evidence, analogy and teaching prerequisites.
5. Choose **Save on this device** if you want browser persistence, or **Download map** for a portable JSON file. **Open a map file** restores that file without a key or a provider call.

A background run remains reachable through **Tracing…**, **Map ready**, or **Trace paused** in the header. Removing a map offers **Undo removal** for the current session. Starting another exploration retains earlier maps in **My maps** for the current session. Switching between Browse and Research preserves the research workspace; returning to Browse restores its previous search/topic context. Reloading or closing the tab discards unsaved maps and recovery checkpoints. The key also disappears unless you explicitly selected **Remember API key on this device** in Settings. Your model choice is saved locally. A browser leave warning helps prevent accidental loss; it is not a substitute for saving.

**Pause and recovery.** If generation ends early but complete source-linked records have arrived, the agent reviews those records and explicitly records the missing coverage; it does not reconstruct unfinished JSON or replay generation. If the final review times out or is incomplete, the map stays inspectable and saveable with an unfinished-review label. No completed-check badge is shown. Completed source retrieval and whole, quoted insights stay in tab memory when a model request is interrupted. **Resume exploration** restarts only the unfinished stage; **Resume evidence check** reuses the existing draft. Partial maps remain inspectable and can be saved or downloaded, with an explicit unfinished-check label. A downloaded partial map preserves the received map, not the session's recovery state. Resuming is a user action that can incur another provider charge. No model is silently substituted.

## Where information goes

| Information | Location / recipient |
|---|---|
| API key | Tab memory, or localStorage when **Remember API key on this device** is selected. Sent only as an authorization header directly to `api.siliconflow.cn`; never included in map files or sent to the atlas server. |
| Research question | Tab memory; sent to SiliconFlow and scholarly and reference search services during a requested run. Never included in atlas API URLs or uploaded to the atlas server. |
| Public atlas index | Compressed, hashed shards pinned to one release; cached in a separate local IndexedDB store (128 MiB bound) and ranked in a Web Worker. |
| Generated map | Tab memory until explicitly saved or downloaded. |
| Saved map | IndexedDB in this browser, scoped to this site's origin. A separate metadata index lists the library without parsing every map. Other devices and browsers do not receive it. |
| Portable copy | A JSON file in the user's chosen download location; it contains no API key. |
| Receipts | Exact model, stage, outcome, prompt/input hashes and provider-reported tokens; included with the map. |
| Recovery checkpoint | Tab memory only; source passages and the last completed stage, without credentials. Discarded on reload. |

SiliconFlow, Crossref, Europe PMC and Wikipedia receive the requests sent to them and may retain data under their policies. This app cannot promise third-party nonretention. Anyone with access to the same browser profile can read saved maps and remembered credentials. **Clear API key** removes the key from this tab and saved settings. Clearing site data removes browser saves; use a downloaded file for a durable or transferable copy. Different local ports and the hosted site have separate browser storage.

No analytics, server-side agent, provider proxy, credential endpoint, result upload, or automatic saving is introduced. The read-only server cannot publish a personal map into the atlas. Opening the exploration page alone does not contact external services.

Ordinary **Browse the atlas** searches still use the public reader's search API. Typing into **Trace a discovery** does not. Moving an existing atlas search into Research does not retroactively make that earlier public-collection search private.

## Evidence and limits

The explorer searches **Crossref and Europe PMC**, plus published atlas explanations. Bounded Wikipedia lookups seek the canonical technique, its key enabling mechanism, up to three proposed foundations plus two intermediate operations from the planned route (or up to five foundations when no intermediate references are proposed), and, when distinct, the original qualified request. All remain within eight lookups and four concurrent requests. The initial query overview helps ground planning. A manufacturer page cannot displace the canonical technology explanation. The intermediate mechanism matters: retrieving only a law and a modern application can leave the crucial bridge unexplained. Exact article titles are tried before search; these are explicitly labeled secondary references, not primary discovery evidence. Revision links, author credit and CC BY-SA 4.0 license links accompany the retained quotations, including in exported maps. It follows at most four DOI references and reads up to three openly licensed explanatory articles through Europe PMC. These are bounded public services, not an unrestricted web browser. Books, paywalls, inaccessible works and historical attribution remain coverage limits. Metadata-only records cannot support a claim.

The planner chooses a directly relevant governing principle before consulting the atlas catalog. An absent foundation can be searched in general references; a vague available law must not replace a more useful missing one. Public adjacency lets it find related atlas explanations locally. This does not create an edge in the personal map: every new connection still needs its own warrant. Source selection reserves space for foundations and explanatory text. Insight writing and connection writing are separate bounded requests, so the connection pass sees the full set and can join parallel mechanisms without treating writing order as causality.

The model selects numbered excerpts; the browser supplies their exact, short quotations. Every admitted insight and connection needs an inspectable quotation. A documented bridge may have a different source from either endpoint. Scientific synthesis must show explicit reasoning and assumptions; it cannot assert historical influence. Teaching links describe how one concept helps explain another. Older files without a declared basis retain their conservative common-source validation. A quotation match is inspectability, not proof.

Nodes have explanatory roles: **Foundation**, **Enabling idea**, **Requested result**, or **Boundary or tradeoff**. A separate model check assesses support and whether a purported foundation is general enough or a result actually matches the query. Accurate related work can remain while losing an inappropriate role. Each arrow has an independent check of direction, scope and warrant. A limiting arrow also classifies the actual endpoint roles: the restricted method or claim must point to its restricting condition. A generic affirmative verdict cannot override a failed role check. A premise_for arrow must also be classified as a deductive derivation; a design rationale or component use cannot pass as a proof. Unsupported links are withheld. A route made mainly of teaching links is explicitly labelled a guided reading path, without a claim of historical influence or deduction. A connected route remains an unverified interpretation, not an audited history or transitive proof. Joint premises are displayed together and all must be accounted for in the route indicator. The reader may navigate from a limit toward the method it constrains, explicitly labelled “bounds”; the stored bounded_by arrow still points from method to limit. This navigation does not earn the stricter directed-core diagnostic and never splits a joint bound.

If the checked map lacks a foundation-to-result route, retains an isolated foundation, or connects fewer than 80% of its insights, the agent may make **one targeted refinement**, starting only within the first three minutes, using its specific review feedback and the retrieved sources. When any checked insights survive, this pass preserves them and existing links. It can add at most two missing, source-supported mechanisms and four connections, each with a fresh check. A missing role may be restored; an additional foundation needs a distinct required branch. If a complete core route already exists, it examines connections for isolated insights without adding more nodes. The refinement receives the exact endpoints, predicates and assessments of withheld arrows so it can address the missing concept rather than repeat a rejected proposal. A full replacement is allowed only when no checked insight survived and the request budget permits it. Progress explains this extra pass. It never fills an evidence gap merely to make the graph connected. Remaining gaps, disconnected insights and missing endpoints are visible. All generated maps remain **unverified drafts**; no qualified human review is implied.

### Operational bounds

A new map targets six substantive insights (up to eight for a distinct required branch), followed by at most 10 proposed connections; portable files support up to 24 insights and 48 relationships for compatibility. Retrieval retains at most 60 sources. There are at most four focused follow-up queries, four DOI lookups, three full-text article downloads, and up to eight targeted general-reference lookups after the initial overview. At most four reference lookups run concurrently. Exact title and search share a 20-second deadline; an overlong mechanism name can try one shortened title/search pair within that same deadline. Source requests have time and size bounds. Main source packets contain at most 16 sources and 24,000 passage characters. Selection and review use only retrieved text; no source can supply a tool URL or authorize an action.

Planning has a 45-second total limit. Insight generation has a 150-second limit and the separate connection pass has a 90-second limit. Each evidence-review pass has a **shared 60-second deadline**, with at most four small checks in flight. Complete checks are cached in tab memory; explicit resume requests only unfinished checks. The normal request count depends on the number of arrows. A session permits at most **24 model requests**, including compatibility adjustments, at most two format repairs, optional semantic refinement and manual resumptions. These limits do not enforce a currency budget. Receipts show exact model identity, request hashes, outcomes and reported usage; missing usage is never treated as zero cost.

A completed empty drafting object has no records for a syntax repair to recover. An unmistakable copy of the input packet is also stopped early through exact prefix comparison. Either can use the same single semantic-refinement allowance for one fresh composition from the original evidence. Repeated failure stops; an explicit evidence-gap response does not trigger this recovery. Both attempts are recorded, and a stopped stream with unreported usage may still be charged.

Insight and connection drafting request a bounded 1,024-token thinking budget. Every node and relationship check requests a 512-token reasoning budget. Node checks use batches of at most two insights. Completed individual verdicts are retained even when a batch omits one. At most two bounded follow-ups assess only unresolved records under the same 60-second deadline; provider failures are not replayed. Planning requests 512 reasoning tokens; format repair requests 128. The planning response uses JSON-object mode. In live GLM testing, disabling thinking was ignored and exhausted the answer allowance; the explicit small budget returned a usable plan. These are requested limits, not provider guarantees. The adapter reserves a separate 1,024-token allowance because some backends count reasoning inside `max_tokens`. Reasoning text is neither displayed nor retained in maps; diagnostic counts are recorded. A requested setting is not proof that a backend obeyed it.

Insight and connection drafting use JSON-object mode to avoid nested strict-decoder failures observed in live comparisons. Planning also uses JSON-object mode; small review requests use output schemas; local identifier, quotation and evidence checks remain authoritative in every mode. Continuous formatting whitespace does not extend the idle deadline. Explicit HTTP 400/422 rejections of optional format or thinking fields permit bounded compatibility adjustments for the same model within the original deadline. This also handles concurrent rejections consistently. Timeouts, rate limits, authentication failures and started generations are not automatically replayed. Rate limiting stops further automatic provider work. The selected model is never silently replaced. Account model discovery does not certify current service availability.

A response that literally copies the example insight fields or uses placeholder warrants is rejected. The single semantic-refinement allowance can instead request one replacement composition from the same evidence, with both attempts retained in receipts. Genuine missing evidence is not treated as a template error.

The final progress heading, **Evidence check finished**, describes completion of the check. The map separately states whether its explanatory path is incomplete. The output reserves one result slot, up to two foundations and up to five enabling insights or limiting conditions. The application assigns stable IDs to each section, so repeated model numbering cannot delete a different insight or the requested result. Complete singleton objects in result/root sections are accepted like one-item arrays. Completed JSON with misplaced sections, incompatible roles or unsupported subject/kind labels requests a bounded format repair instead of silently truncating mechanisms. Repair may move existing records, but cannot invent missing claims or evidence. Unfinished objects are never reconstructed. This prevents multiple applications from taking the requested-result role and preserves the result early in a stream. Streaming retains complete insights and whole connections separately. If the connection pass is interrupted after complete arrows have arrived, those arrows proceed to review without regenerating the insights or replaying the request. An optional refinement that returns no usable insights or removes all earlier connections retains the earlier checked map. A partial map is inspectable, saveable and clearly marked; incomplete JSON is never reconstructed.

Discovery attribution and dates are checked independently of the scientific claim.
Unestablished credit stays unspecified; a source's author or publication year does
not automatically identify the discoverer or discovery date. Historical links are
withheld when their required chronology is no longer supported. Each small review
batch judges its own records; it cannot make whole-map absence claims.

## Implementation

- `web/src/explore/agent.ts` and `prompts.ts`: bounded retrieve–plan–retrieve–draft–challenge workflow and prompt boundary.
- `sources.ts`, `articles.ts` and `references.ts`: direct scholarly retrieval, licensed excerpts, foundation discovery and browser-local atlas adjacency.
- `provider.ts`: one fixed SiliconFlow endpoint, model discovery and nonsecret receipts.
- `contracts.ts`, `review.ts` and `verify.ts`: output contracts, independent checks, complete-verdict accounting and resumable review.
- `assembly.ts`, `excerpts.ts` and `lineage.ts`: insight-section normalization, exact excerpt selection and dependency-aware navigation.
- `stream.ts`: bounded streaming, cancellation, idle detection and complete-object extraction.
- `progress.ts` and `ExplorationProgress.tsx`: stage evidence and explicitly approximate time ranges.
- `model.ts`: draft contracts, deterministic admission checks, graph adaptation and import validation.
- `library.ts`: explicit IndexedDB saves and portable export.
- `settings.ts` and `Settings.tsx`: global provider configuration and explicit local key persistence.
- `Explorer.tsx`: reader workflow; reuses the existing graph renderer and predicate registry.

The reader exposes a versioned `/api/exploration-manifest`, bounded `/api/exploration-shard` responses and `/api/exploration-records` for at most 40 full-record IDs per request. All are public, snapshot-pinned data; matching runs locally without a 10,000-record cutoff. The server can see requested shard and record IDs, which may reveal the public subjects being read, but does not receive the personal research prompt. The legacy paginated `/api/exploration-index` remains available for compatibility. [API contract](API.md).

Live 1.5 browser acceptance includes the six requested queries and multiple exact model IDs. Timings and completeness vary; some runs received HTTP 429 responses or timed out, and a completed review can leave an incomplete graph. All outcomes and known usage are retained in the [acceptance report](../reports/acceptance-1.5.md). Bulk authoring and browser tests sharing one provider account can contend for its rate limit. A discovered model ID is not a service guarantee.

API references: [SiliconFlow models](https://docs.siliconflow.cn/docs/api/models-get), [chat completions](https://docs.siliconflow.cn/docs/api/chat-completions-post), [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/), [Europe PMC REST services](https://europepmc.org/RestfulWebService), [MediaWiki API](https://www.mediawiki.org/wiki/API:Main_page).

### Known source conflicts

A small revision-specific ledger excludes inspected reference revisions with known contradictions from new explorations. It is a source-quality finding, not qualified human certification. Older maps remain reproducible and inspectable, with a visible warning and a link to the conflicting primary source; their records are not silently rewritten. The first finding concerns an overbroad SIMT description contradicted by NVIDIA’s documentation of independent thread scheduling for Volta and later GPUs. A different revision is not automatically excluded. See [the inspectable ledger](../web/src/explore/sourceQuality.ts). This does not certify other references or detect every source error.

For a technological or empirical requested result, the bounded connection composer focuses on documented use, explicit synthesis, limits and teaching links rather than proposing a deduction of the device or observed outcome. Formal theorem endpoints retain deduction proposals. The shared predicate registry, canonical records and independent review meanings are unchanged. During refinement, restoring a missing requested result and general foundation takes priority over optional new mechanisms; unsupported essentials remain gaps.
