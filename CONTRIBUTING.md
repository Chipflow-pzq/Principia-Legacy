# Contributing

A useful contribution makes an idea easier to understand, its evidence easier to inspect, or a mistaken interpretation easier to correct.

## Scientific content

Propose one specific intellectual move. Include:

- **The idea:** what problem it addresses and what changes in the explanation or method.
- **The evidence:** an inspectable source, its version, and the relevant passage or page.
- **The credit and limits:** who is supported by the source, applicable assumptions, counterevidence and unresolved questions.

For an existing record, include its ID, release and revision. A correction must explain what changes and why. For a relationship, justify the connection itself; proximity in time or a shared citation does not establish influence. See [the record contract](docs/CONTRACT.md) and [authoring guide](docs/AUTHORING.md).

Use an issue for an evidence question or a proposed interpretation before investing in a large batch. Do not reproduce copyrighted papers or supply material you lack permission to share. Preserve independent discoveries and report uncertainty rather than guessing attribution.

## Code and reading experience

Describe the reader's problem and the expected behavior. Keep changes focused, readable and lightweight. Follow [the development guide](docs/DEVELOPMENT.md), run checks relevant to the change, and include a screenshot for visible interface changes. A visual improvement must preserve keyboard access and narrow-screen usability.

## Review and trust

Machine checks and expert review are separate. Human review requires a real reviewer-authored attestation of the exact revision and scope checked. Please state relevant expertise and conflicts of interest; never attribute a human review to an agent or a model run.

Code contributions use MIT. Original explanations use CC BY 4.0. Third-party rights remain separate. [Governance](GOVERNANCE.md) describes the correction and review policy; [security reporting](SECURITY.md) covers private vulnerabilities.
